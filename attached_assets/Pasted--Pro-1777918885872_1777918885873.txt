أحتاج منك تنفيذ مراجعة هندسية شاملة وإعادة بناء للأنظمة الداخلية في مشروعي الحالي بهدف تحويله من Prototype إلى منصة Production-ready قابلة للإطلاق الفعلي.

يرجى التعامل مع المشروع كمنصة مالية/إعلامية حقيقية تتطلب أعلى مستوى من الأمان، الدقة، وقابلية التوسع.

أولًا: تقييم الوضع الحالي

المشروع يعاني من المشكلات التالية:

1) نظام الأخبار ضعيف
الاعتماد على مصادر محدودة جدًا
لا يوجد تنوع أو موثوقية في مصادر الأخبار
لا يوجد نظام تجميع أو تصفية احترافي للأخبار
2) لا يوجد Backend حقيقي
النظام يعتمد بالكامل على localStorage
لا يوجد Server-side logic
لا يوجد نظام تحقق حقيقي للمستخدمين
3) نظام VIP غير آمن
يمكن التلاعب به بسهولة من المتصفح
لا يوجد تحقق من السيرفر
لا يوجد إدارة اشتراكات حقيقية
4) مفاتيح API غير آمنة
مفاتيح API موجودة في Frontend
هذا يمثل خطر أمني كبير
5) لا يوجد نظام دفع حقيقي
الدفع يتم يدويًا
لا يوجد ربط تلقائي بين الدفع وتفعيل الاشتراك
6) بيانات الأسواق غير حقيقية
الأسعار ثابتة أو غير دقيقة
لا يوجد ربط مباشر بمصادر بيانات مالية حقيقية
ثانيًا: المطلوب تنفيذه
1) إعادة بناء نظام الأخبار
استخدام مصادر API متعددة مثل:
NewsAPI
Finnhub News
دمج مصادر مختلفة للحصول على تغطية أوسع
إنشاء نظام backend يقوم بـ:
تجميع الأخبار
إزالة التكرار
ترتيب الأخبار حسب الجودة والأهمية
ضمان استقرار النظام بعد النشر
2) إنشاء Backend باستخدام Node.js

يكون مسؤولًا عن:

إدارة المستخدمين
نظام Authentication كامل
إدارة الاشتراكات (VIP)
جلب الأخبار من المصادر الخارجية
جلب بيانات الأسواق

ويجب أن يكون التصميم:

Modular
قابل للتوسع
منظم بشكل احترافي (Clean Architecture أو ما شابه)
3) تأمين مفاتيح API
نقل جميع مفاتيح API إلى environment variables
منع الوصول إليها من Frontend نهائيًا
جعل كل الاتصالات مع APIs الخارجية تمر عبر Backend فقط
4) بناء نظام VIP حقيقي
نظام تسجيل دخول كامل (Authentication)
تخزين المستخدمين في قاعدة بيانات
التحقق من حالة الاشتراك من خلال السيرفر فقط
منع أي إمكانية للتلاعب من جهة العميل (Client-side)
5) دمج نظام دفع احترافي
استخدام Stripe كنظام دفع رئيسي
إنشاء نظام اشتراكات (Subscriptions)
تفعيل VIP تلقائيًا بعد الدفع عبر Webhooks
ربط حالة الدفع مباشرة بقاعدة البيانات
6) ربط بيانات الأسواق المالية
استخدام APIs حقيقية مثل:
Finnhub
Alpha Vantage
توفير بيانات لحظية أو شبه لحظية للأسعار
استخدام caching لتقليل الضغط على APIs وتحسين الأداء
7) الأمان (Security Layer)

يجب تنفيذ مراجعة أمنية كاملة تشمل:

حماية جميع API endpoints
تأمين نظام Authentication (JWT / Sessions)
منع التلاعب من المتصفح
إضافة rate limiting
حماية البيانات الحساسة
منع تسريب المفاتيح أو استغلال النظام
ملاحظات مهمة جدًا
ممنوع تغيير تصميم الموقع الحالي (UI/UX يجب أن يبقى كما هو)
التركيز فقط على:
Backend
Data Layer
Security
المتطلبات النهائية للكود
نظيف (Clean Code)
منظم وقابل للتوسع
Production-ready
قابل للنشر مباشرة
الهدف النهائي

تحويل المشروع من نموذج تجريبي إلى منصة حقيقية تتميز بـ:

أمان عالي
استقرار في البيانات
نظام VIP حقيقي
بيانات سوق وأخبار موثوقة
قابلية توسع مستقبلية
